# 资料库总索引

> AI 找资料时**先读这个文件**，再按路径去取，不要盲扫整个目录。
> 新增资料后必须回来补一行，否则等于没存。

## 目录约定

| 目录 | 装什么 |
| --- | --- |
| `work/projects/` | 按项目一文件，写背景、决策、客户偏好、交付规范 |
| `work/templates/` | 可复用的模板（周报、方案、评审） |
| `notes/` | 个人知识笔记，一文件一主题 |
| `links.md` | 常用网站、工具、文档入口 |

## 索引

| 资料 | 路径 | 一句话说明 | 更新 |
| --- | --- | --- | --- |
| 示例：某客户交付规范 | `work/projects/示例客户.md` | 标题 16px、主色 #1890FF、圆角 8px | 2026-09 |
| 示例：报销流程 | `notes/报销流程.md` | 三步走完，票据要留 90 天 | 2026-09 |
| 示例：常用参考链接 | `links.md` | 会反复打开的文档与工具入口 | 2026-09 |

## 命名与写法

- 一文件一主题，文件名用中文短语，能望文生义（`客户A交付规范.md` 优于 `doc1.md`）。
- 每个文件开头写一段 `> 摘要：`，一两句话，索引里直接引用它。
- 大文件（PDF、图片、PPT）放进 `work/assets/`，在对应笔记里用相对路径引用，别把二进制塞进 Git 历史。
