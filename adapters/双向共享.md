# 和本机的 Agent 应用互通（双向共享）

> 一句话：**两个 AI 应用默认各记各的，不会自动共享**；`tools/bridge.py` 是那座桥，跑一次就通。

## 一、为什么默认不共享

WorkBuddy、LobsterAI、Cursor 这类「装在电脑上的 Agent」，各家的记忆都放在自己的私有目录里，互不读取。
它们唯一共同的地方是：**每次启动都会读自己目录下的某个记忆文件**。
所以让它们共享的办法不是求它们互通，而是——把它们要读的那份文件，换成同一份内容。

## 二、桥是怎么工作的

```
        ┌─────────────────────────┐
        │  AIBrain（唯一事实来源）│   memory/ + knowledge/
        └───────────┬─────────────┘
        sync.py 编译│
        ┌───────────▼─────────────┐
        │ dist/portable-full.md   │  一份文本，内容同上
        └───────────┬─────────────┘
     bridge.py push │（带标记的区块，可反复重跑）
      ┌─────────────┴──────────────┐
      ▼                            ▼
 .workbuddy\MEMORY.md    ...\workspace-main\MEMORY.md
 （WorkBuddy 每次读）     （LobsterAI 主会话读）
```

- 区块被 `<!-- AIBrain:begin ... -->` 和 `<!-- AIBrain:end -->` 包住。
  **区块外的内容是你自己的**，随便写；区块内是自动推送的，下次推送整体替换，不会越滚越长。
- 反向也有一条路：`bridge.py pull` 会把「应用里写过、AIBrain 里还没有」的条目捞成一份候选清单
  （写到 `inbox/`，**不自动入库**），你复核后再决定要不要并进 `memory/`。

## 三、怎么用

```bash
python tools/bridge.py status     # 看接上没有、区块是不是最新的
python tools/bridge.py push       # 把 AIBrain 推给所有应用（自动先跑 sync.py）
python tools/bridge.py push --compact   # 推精简版（省上下文，内容更少）
python tools/bridge.py pull       # 把应用里的新记忆捞回候选清单
python tools/bridge.py push --dry-run   # 只预览，不写文件
```

改记忆的正确姿势，三步：

1. 改 `memory/`（不要改 `dist/`，也不要改别的应用里的区块）；
2. `python tools/sync.py` 重新编译；
3. `python tools/bridge.py push` 推给各应用，下次它们启动就是新记忆。

## 四、已经接好的应用

| 应用 | 注入到哪个文件 | 为什么是这个文件 |
| --- | --- | --- |
| WorkBuddy | `~/.workbuddy/MEMORY.md` | 用户级长期记忆，每次对话自动加载，跨项目生效 |
| LobsterAI | `%APPDATA%\LobsterAI\openclaw\state\workspace-main\MEMORY.md` | 它 `AGENTS.md` 里写明「主会话启动时加载 MEMORY.md」 |

**想再接一个应用**（Cursor、Claude Code 等）：打开 `tools/bridge.py`，在 `APPS` 列表里照着加一条，
只需要两样东西——**它启动时必读的记忆文件路径**，以及想顺带扫描的日志/档案路径。
规则文档类（Cursor 的 `.cursor/rules`、Claude Code 的 `CLAUDE.md`）用同样思路：写一句「去读 AIBrain」即可，
那种场景用 `adapters/README.md` 里写的挂载方式更省事。

## 五、安全与边界

- **push 前会自动备份**被覆盖的文件到 `AIBrain\.backup\bridge\`（这个目录不入 git），改错了能翻回去。
- 区块**只替换自己那一段**，绝不碰你在文件里写的其他内容。
- **pull 只读**：它只读应用的记忆文件，不写、不改、不删。
- 云端平台（ChatGPT / 豆包 / Kimi 等）**没有本地文件可注入**，只能靠上传 `dist/portable-full.md`
  或粘贴 `portable-compact.md`，见 `adapters/README.md`。

## 六、常见疑问

- **同一个应用会不会读到两份互相矛盾的记忆？**
  不会。记忆只在 AIBrain 里存一份，应用读到的是它的编译副本；你要是手改了区块，下次 push 会被覆盖回来。
- **换了电脑怎么办？**
  `APPS` 里的路径是跟着系统盘走的（自动取用户目录与 `%APPDATA%`），在新机器上跑一次 `push` 重新注入即可；
  记忆本身跟着 git 走。
- **区块里会有我的隐私吗？**
  有——它就是你 `memory/` 里的内容。所以这个仓库默认私有，公开模板走 `tools/make_public.py` 生成副本。

## 七、想少敲命令：做成桌面双击脚本

Windows 上建一个 `.bat` 放桌面（路径换成你自己的，**文件必须存成 GBK 编码**，否则中文乱码）：

```bat
@echo off
chcp 936 >nul
cd /d "<你的路径>\AIBrain"
"<你的 Python 路径>" tools\bridge.py push
"<你的 Python 路径>" tools\bridge.py status
pause >nul
```

macOS / Linux 同理，写个 `.command` / `.sh`，里面就是那两行 `python3 tools/bridge.py ...`。双击即同步。
