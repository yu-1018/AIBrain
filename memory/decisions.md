# 已定的决策与理由

> 这个文件专门回答「当初为什么这么定」。半年后你只会记得结论，所以**理由和否掉的备选才是重点**。

## 2026-03-12 · 支付中台统一收口到中台团队，而不是各业务线各自维护

- **背景**：多条业务线各自接支付渠道，重复开发、对账口径不一致。
- **决定**：建统一支付中台，各业务线通过标准 API 接入，由中台团队统一维护渠道与对账。
- **理由**：减少重复、对账口径统一、故障可集中治理。
- **否掉的备选**：各业务线各自维护（烟囱式、口径分裂）；直接采购 SaaS（定制能力弱、数据在外）。
- **影响**：业务线接入需走中台排期，新渠道上线节奏受中台约束。
